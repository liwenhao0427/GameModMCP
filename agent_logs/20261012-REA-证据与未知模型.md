if (limitations.length > 0) return "unknown";

`ReconstructionObligationLedger.closure.test.ts:34-88` —— 把 fixture 与 verifier

### 6. 比较类工具的保守性（8 个代码点）

1. provider 不同不比文本：`functionComparisonDimensions.ts:69-79` →

### 7. 传输预算

- `MINIMUM_RESPONSE_BYTES = 10 * 1024 * 1024`（`mcpResponseBudget.ts:9`）；
  `resultBudgetBytes = maximumResponseBytes - 1024`（`toolResult.ts:24-27`）。
- **先判定再构造**（`toolResultEncoding.ts:37-66`）：遍历分片、边量边累加，
  **越界立即返回** `{ok:false, bytesAtLeast, codeUnitsAtLeast, constraint}`，
  不把剩余拼出来。注释：「Account for the delivered JSON representations before
  allocating the complete text」（:36）。
- **成功/错误分开计费**：成功 = structuredContent + text 两份；
  错误 = 只有 text 一份（:8-24）。
- **超限不截断**：`toolResult.ts:136-178` 转成 `resource_constraint`，
  消息明说「The analysis result was not truncated.」（:162），
  `response_bytes_at_least` 是**真实下界**（遍历在越界处停了）。
- **连错误超大也不丢证据**：`EvidenceMcpServer.ts:219-285` 先存完整错误进台账，
  再返回带 `evidence_reference` 的小错误（保留失败时如实写
  `retention: "failed"|"unavailable"`）。
- **不搬大对象**：`get_evidence_bundle(detail:"summary")`
  （`evidenceRecordSummary.ts:117-166`）**不读也不复制 `normalized_result`**。

## 对我们项目的 5 条（该子 Agent 的原文结论）

1. **证据成为一等对象 + 语义哈希 id** —— 我们的「静态 token == 运行时 token」
   目前只活在返回文本里，无法引用/比对/防篡改。
2. **残余未知台账** —— 我们现在遇到失败只写一句 `error`，**未知被丢弃了**；
   可直接把 `is_64: None`、`gc_control` 不支持等升级为带 `recommended_probes`
   的 open/out-of-scope unknown。
3. **不可变追加 + CAS** —— `set_field_value` / `write_memory` 可避免基于**过期读值**
   写内存（Hook 场景尤其重要）。
4. **关门规则显式编码 + 证据层级不可互相顶替** —— 可照抄成
   `hook_target_confirmed` 义务，要求 `proof_authority == live-runtime`，
   这样「只查元数据就说落点对了」**结构上无法通过**。
5. **预算先判定再构造** —— 我们 `cap.py` 每次先构造完整 payload 再量；
   在 `search_classes('', limit=2000)` 的 856 KB 上可省掉一次完整序列化。
