# 三个 MCP 项目调研：AI Agent 如何操作并验收运行中的游戏

## 1. gua-project/gua（C# / C++ 原生核心 + TS MCP）

**工具面（`packages/mcp/src/index.ts` 的 `guaMcpTools`，65 个）**：`get_ui_tree`、`wait_for_node`、`get_screenshot`、`get_logs`、`get_clock`/`clock_install`/`clock_pause`/`clock_run_for`/`clock_resume`、`start_recording`/`stop_recording`/`save_recording`/`replay_recording`、`compare_screenshot`、`get_visual_artifacts`、`run_test`、`get_world_object_tree`/`find_world_objects`/`wait_for_world_object`、`get_spatial_info`/`query_spatial_batch`、`click_node`/`focus_node`/`set_value`/`set_checked`/`select`/`scroll`/`press_key`，以及原始输入 `key_down`/`key_up`/`press_physical_key`（参数 `code` 为 W3C `KeyboardEvent.code`，如 `KeyW`；`leaseMs` 1–60000）、`pointer_move`（`mode` absolute|delta、`coordinateSpace`）、`pointer_button_down/up`、`pointer_wheel`、`gamepad_*`、`text_input`（`text` maxLength 40）。

**语义定位**：核心即 Semantic UI Tree，明确「不依赖图像识别或屏幕坐标」。C# 侧有选择器记录 `GuaSelector(Id, Role, Name, Text, ParentId, Visible, Enabled)`，每项配 `GuaMatchMode{Exact,Contains,Regex}`——这是 CSS selector / PageObject 的等价抽象。API 形如 `GuaAssertions.GetByRole(ui,"button","Start Game").Click()` 与 `expect(game.getById("loading")).toBeVisible()`。录制回放里 `resolveTarget` 支持 `target.id` 或 `role + name + scope`，且**匹配到 ≠1 个节点就报错**（拒绝猜）。

**等待与稳定性**：`wait_for_node`（`timeoutMs`，`waitForNode` 内部轮询）、`wait_for_world_object`、`run_test` 的每步 `timeoutMs`。`Click()` 只是**入队请求**，需适配器在后续帧消费并回发事件。录制回放的 `waitForCondition` 支持 `visible/hidden/enabled/disabled/focused/unfocused/checked/unchecked/text/value` 条件串，50ms 轮询到超时。另有 `GuaClock` 虚拟时钟（`Pause` / `RunFor`）消除墙钟等待。

**验收/断言与 evidence**：断言由 `Gua.Testing` 在 NUnit 内提供（`GuaDiagnosticsSession`），失败时统一收集 artifacts；另有 `GuaSemanticSnapshots` 语义快照（`ExpectSnapshot` 抛 `SemanticSnapshotAssertionException`，可带 reason / baseline 路径 / artifact 路径 / run ID / 逐条差异）与 PNG 视觉基线（`compare_screenshot` 参数 `name`、`variant`、`updateBaseline`、`pixelThreshold`、`maxDifferentPixelRatio`、`masks[]`；失败写入 `actual.png`/`expected.png`/`diff.png`/`comparison.json`）。**明确要求「入队受理 ≠ 完成」**：动作返回 `requestId` 后要轮询关联的 host completion，未确认时报 `outcome: completion_unconfirmed` + `stage`，且「不要自动重试未确认的动作」。

**通信通道**：游戏内原生 runtime 起 WebSocket bridge（默认 `ws://127.0.0.1:8765`），`gui-mcp` 是薄 MCP 代理；另有 WebMCP 浏览器通道。

**已发布游戏 / 反作弊**：**这是三家里唯一正面处理的**。Gua 明确支持 release build 里 AI 当玩家：`GuaAgentPolicy` 可 omit/redact/replace/quantize 字段并限制 UI 动作；`GUA_OBSERVATION_PROFILE=player` 在 transport 之前就投影 UI 与 World 树，客户端**无法提权**；screenshots 在 player 模式默认禁用。Unity 侧支持 Editor Play Mode **与已构建的 desktop Mono Player**（Windows/Linux/macOS，Mono only；**IL2CPP、IMGUI、EditorWindow 不支持**）。

## 2. FunplayAI/funplay-unity-mcp（Unity Editor 内嵌 HTTP MCP）

**规模**：`full` 180 个工具 / 42 模块，`core` 默认 40 个。

**输入模拟**（`Editor/Tools/Builtins/InputSimulationFunctions.cs`）：`simulate_key_press(key, duration, action=press|release|tap)`、`simulate_key_combo(keys, duration=0.5)`、`simulate_mouse_click`、`simulate_mouse_drag(start_x, start_y, end_x, end_y, duration=0.5, button=left, coordinate_space=render_pixels, origin=bottom_left, capture_id)`、`simulate_ui_scroll`。均**先校验 `EditorApplication.isPlaying`**，否则报 `PLAY_MODE_REQUIRED`；用 Input System 的 `InputSystem.QueueEvent` + 显式 `InputSystem.Update()`，并支持逐像素插值（`steps = max(5, duration*30)`）。

**截图/视频**：`capture_game_view`、`capture_simulator_view`、`capture_scene_view`、`capture_multiview`、`capture_editor_window`；`record_game_view`（MediaEncoder 静音 MP4，`action=start|status|stop`、`duration_seconds` 1–120、`fps` 1–60、`max_dimension` 128–1920）、`mark_recording`、`extract_recording_frames`、`get_recording_frame`。

**等待/轮询**：统一走 `get_task`（`task_id`、`kind`、`request_key`、`after_revision`、`wait_seconds` 0–30 默认 20、`offset`、`limit`）。设计要点：返回 `revision` + `poll_after_ms`，**状态未变时退避 1→2→5→10 秒**，「不要让模型每秒轮询一次」；`wait_seconds=0` 表示立即返回；`wait_complete` 明确「只代表这一轮等待结束，不代表成功」。另有 `wait_for_compilation`、`get_reload_recovery_status`。

**验收/断言**：**没有断言工具**——它把证据交给 Agent 判断。工具返回 `{success, message, data}`（`Editor/Tools/Helpers/Response.cs`）。截图用「native image + 结构化文本元数据」而非 base64 文本；`capture_id` 有 30 秒有效期，且校验 domain / Play 状态 / 视图 / 相机布局 / 渲染尺寸，过期报 stale-geometry 错误。`RecordingFramesJob` 每个 frame 带 `requested_seconds/actual_seconds/delta_seconds` 与 `selection_policy`（明说「不保证最近帧或精确时间」）。`audit_ui` 产出 finding（含 measured evidence、suggestion、runtime-verification requirements），`run_tests` 走 Unity Test Runner（返回 `failCount/passCount/skipCount/inconclusiveCount`、`success`、`failedTests[]`）。

**通道与限制**：**Editor-only，明确声明「不在你的游戏构建里添加任何运行时组件」**。Editor 内嵌 HTTP JSON-RPC（Streamable HTTP，端口按项目派生 20000–29999），可选 Experimental Broker Mode 用 Unity 自带 Mono 维持重连。**完全没有涉及已发布游戏注入或反作弊场景**。

## 3. notargs/UnityNaturalMCP（MCP C# SDK，Preview）

**工具（仅 5 个，README 与源码一致）**：`RefreshAssets()`、`GetCurrentConsoleLogs(logTypes[], filter, maxCount=20, onlyFirstLine=true, isChronological=false)`、`ClearConsoleLogs()`、`RunEditModeTests` / `RunPlayModeTests(assemblyNames[], categoryNames[], groupNames[], testNames[], cancellationToken)`。另在 `McpUnityEditorTool.cs` 里还有 `GetCompileLogs`（= `ClearConsoleLogs` + `GetCurrentConsoleLogs({"compile-error","compile-warning"})`）。

**语义定位 / 输入模拟 / 截图**：**均未提供**（无 UI 元素定位、无 input simulation、无 screenshot 工具）。

**等待与断言**：`RunTests` 用 `TestResultCollector.WaitForRunFinished(token)` 等待，并用 `CompilationErrorLogHandler` 在出现 `"All compiler errors have to be fixed before you can enter playmode!"` 时取消。返回结构见 `TestResults.cs`：`failCount/passCount/skipCount/inconclusiveCount`、`failedTests[]{name, fullName, resultState, testStatus, duration, message, stackTrace, output}`、`success => (failCount+inconclusiveCount)==0 && passCount>0`。这是三家最像「断言即工具返回值」的一个。

**通道**：`UnityNaturalMCPServer` 作为 **Streamable HTTP** 服务器跑在 Unity Editor 内（默认端口 56780），Client 可直连；不支持 HTTP 的客户端（如 Cursor）经 Node.js 的 `mcp-stdio-to-streamable-http` 中转。**仅 Editor，完全没有涉及已发布游戏或反作弊**。README 已知限制：域重载会断连导致 run tests 失败，需关闭 Enter Play Mode 的 Reload Domain。

## 对本项目可借鉴的 4 条

1. **动作结果必须区分「已提交」与「已完成」**。Gua 把 `not_sent` / `completion_unconfirmed`（再分 `awaiting_receipt`/`awaiting_completion`/`awaiting_observation`）做成一等返回字段，并明令「未确认不要自动重试」。本项目的 `hook_method`/`launch_game` 同理：装了 Hook ≠ 已生效，应有明确的确认态与 `requestId` 关联轮询，而不是把「调用没抛异常」当成功。

2. **轮询要有 `revision` + `poll_after_ms`，而不是让 Agent 每秒自发轮询**。Funplay 的 `get_task` 在状态未变时退避到 1→2→5→10 秒，并要求 Agent 遵守该延迟。本项目 `drain_events` 是「取走即消费」，可补一个返回当前事件序号的 `revision`，让 Agent 知道「自上次以来是否有变化」。

3. **选择器抽象 + 「匹配数 ≠1 就报错」**。Gua 的 `GuaSelector`（Id/Role/Name/Text/ParentId/Visible/Enabled × Exact/Contains/Regex）与 `resolveTarget` 的「matched N nodes → 抛错」拒绝歧义，与本项目「短名歧义即 `ok:false` + `candidates`、绝不猜」的既有原则同构，可继续强化（例如给 `search_*` 结果加 `MatchMode` 语义）。

4. **证据要成组落盘并带有效期校验**。Gua 失败时统一产出 `actual/expected/diff/comparison.json`；Funplay 用 `capture_id` + 30 秒有效期 + domain/Play/视口一致性校验，过期即报 stale。本项目可在 `hook_method` 成果上补一份结构化「验收证据包」（静态 token vs 运行时 token、命中事件、内存快照），并标注快照的采集时刻与有效性。

> 反向参考：三家**只有 Gua** 正面处理了「已发布游戏 / 商店版」，手段是运行时装原生 bridge + `player` 投影策略（默认禁用截图、客户端不可提权），且 Unity 侧仅 Mono、不支持 IL2CPP。Funplay 与 UnityNaturalMCP 都是 Editor-only，均未提及反作弊绕过——这条恰恰是本项目（注入已发布游戏、IDA/Frida 路线）最需要自己设计的部分。
