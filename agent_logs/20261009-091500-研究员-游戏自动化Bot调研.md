# 游戏自动化 Bot 的「OCR + 点击 + 日志」设计模式调研

## A. 定位 UI 元素

**核心抽象是 ROI/box/target 三分**：`roi` 是识别边界，`box` 是命中区域，`target` 是动作目标，默认
`target=true` 即点 box；`Click` 的 target 可为 `[x,y,w,h]`，"在矩形内随机选点（中心概率高）"
（MaaFramework `docs/zh_cn/3.1-任务流水线协议.md`）。MAA 老协议同构：`action: ClickSelf` 注释即
"点击识别到的位置（识别到的目标范围内随机点）"（MaaAssistantArknights `docs/zh-cn/protocol/task-schema.md`）。

**识别算法可枚举、可组合**：TemplateMatch / FeatureMatch / ColorMatch / OCR /
NeuralNetworkClassify / NeuralNetworkDetect / And / Or / Custom（同上）。**优先级 fallback 就是
`next` 列表的顺序语义**——"按顺序识别 next 中的每个节点，只执行第一个识别到的"；`Or` 则是节点内的
"命中第一个即成功"。即：不做算法级投票，做**节点级短路**。

**分辨率**：MAA 走"基准 720p + 全局缩放系数"。`ControlScaleProxy.cpp:28-58` 先拒绝 <1280×720 与
非 16:9，再算 `m_control_scale = height / 720`，`click()` 里 `x = p.x * m_control_scale`；协议侧 ROI
"以 1280*720 为基准自动缩放"。MaaMCP 把同一机制暴露成 `target_short_side=720` 连接参数。BetterGI 用
`TaskContext.Instance().SystemInfo.AssetScale` 乘坐标（`GameTask/Common/BgiVision/BvOcr.cs:26-28`）。
March7th 用**相对比例 crop(0~1)**，且 >1920 宽时缩到 1920×1080 并回传 `screenshot_scale_factor`
（`module/automation/screenshot.py:224-237`）；另有 `check_resolution` 强校验（5 次 × 10 秒）并用
**注册表改游戏分辨率**（`tasks/game/starrailcontroller.py:21-45`）。ALAS 用基准像素坐标 +
`cv2.matchTemplate(TM_CCOEFF_NORMED)` 邻域搜索（`module/base/button.py:202-236`）。

## B. OCR 引擎

- MaaFramework：**PaddleOCR 转 ONNX**（`model/ocr/{det.onnx,rec.onnx,keys.txt}`，
  `docs/zh_cn/1.1-快速开始.md:179-183`），fastdeploy PPOCRv4 推理，分 `WordOcr`/`CharOcr` 两个单例并支持
  GPU 选择（`Vision/OcrPack.h`）。
- **只 OCR 局部 ROI 是标配**：`OCRer::analyze()` 第一步就是 `recognize(make_roi(m_image, m_roi), ...)`，
  裁出 ROI 再送模型（`Vision/OCRer.cpp:20-30`）；随后做正则 `replace` 纠错、`threshold` 置信度(默认 0.3)、
  `only_rec`（不跑检测，需精确 ROI）。
- ALAS：**自研小模型**（cnocr densenet-lite-gru），关键是**按游戏字体收窄 charset**——
  azur_lane 3.25MB/39 类/99.43%，通用 cnocr 9.51MB/6426 类（`module/ocr/models.py`）。
- BetterGI：PaddleOCR，按**语言矩阵**分裂模型（V4/V5/V6、V4En/V5Korean/V5Latin/V5Eslav，
  `OcrFactory.cs`），`DropScore=0.5`；有 `OcrWithoutDetector`——已知区域内只有一行字时跳过检测模型
  （`BvOcr.cs:44`）。
- March7th：RapidOCR，`EngineType.OPENVINO|ONNXRUNTIME`、`ModelType.MOBILE`、PPOCRV4、
  `Global.min_height=155`（低于该高度跳过文本检测直接识别）；DML 连续变慢自动降级 CPU
  （`module/ocr/ocr.py:659-681, 797-813`）。
- ok-script：OnnxOCR（PaddleOCR v5，OpenVINO 或 ONNX Runtime，支持 Intel NPU）。
- **耗时量级：未获取到**任何项目给出的权威 benchmark 数字，不编造。

## C. 点击与输入

**两套并行通道，后台可用性是一等公民。** MaaFramework 的 input method 枚举直接标注 Background
Support：PostMessage=Yes、SendMessageWithCursorPos=Yes、WithWindowPos=Yes、AnchoredTouch=Yes；
Seize/SendMessage/Interception=No（`include/MaaFramework/MaaDef.h`）。**后台点击的关键是不抢焦点，
而是"骗"窗口**：

```cpp
// 让目标窗口认为自己被激活，但不实际改变前台窗口
PostMessageW(hwnd, WM_ACTIVATE, WA_ACTIVE, 0);
```
（`source/MaaWin32ControlUnit/Input/InputUtils.h:12-26`）

BetterGI 同思路且对称双后端：`Win32InputBackend` "前台 SendInput，后台 PostMessage。两路总是同时可用"，
后台通道每次操作前 `if (User32.GetForegroundWindow() != _hWnd) _simulator.Activate();`
（`Core/Input/Backends/Win32/PostMessageChannel.cs:125-139`）。它还明确记录后台通道的能力边界：
不支持相对移动、中键、侧键、滚轮（warn 后忽略）——比假装支持更可靠。

抢焦点失败兜底：MaaFW `WithWindowPos` 系用 `NtSuspendProcess` 挂起目标 + `SetWindowPos` 挪窗口 +
`SetCursorPos`，结束恢复原位，并有 `is_window_move_allowed` 守卫（不许移出原显示器）与 WH_MOUSE_LL
钩子累加硬件鼠标位移（`Input/MessageInput.cpp`）。

**拟人化抖动**：MAA 用**正态分布 + 拒绝采样**，以矩形中心为均值、边长/3 为标准差，8 次后退化为中心点
（`ControlScaleProxy.cpp:172-202`）；ALAS 用均匀随机 `random_rectangle_point`，滑动时长
`duration=(0.1,0.2)` 区间随机（`module/device/control.py:38,88`）。

## D. 等待与稳定性

MaaFW 把等待写成一句可验证的伪代码：`while(!hit && !timeout) { foreach(next); sleep_until(rate_limit); }`，
**rate_limit 默认 1000ms、timeout 默认 20000ms、-1 为无限**；`pre_delay`/`post_delay` 默认各 200ms。
失败由 `on_error` 承接，触发条件有二：next 全未命中且超时，**或动作执行失败**。

**"画面稳定"是一等字段**：`pre/post/repeat_wait_freezes` 语义为"连续 time 毫秒画面没有较大变化才退出"，
实现是前后帧模板匹配比对，参数 `{time, target, threshold:0.95, method:5, rate_limit:1000, timeout:20000}`
（`3.1-任务流水线协议.md`）。

**"上一步生效了吗"**：MAA 用 `reduceOtherTimes` 显式记录反证——"例如执行了使用理智药，则说明上一次点击
蓝色开始行动按钮没生效，所以蓝色开始行动要-1"（`task-schema.md`）。ALAS 用 `retry` 装饰器
（tries/delay/backoff/jitter/max_delay），最后一次**抛出同一异常**而非吞掉（`module/base/retry.py:55-58`），
并把 `GameStuckError`/`GameTooManyClickError`/`GameBugError` 建模为**具名异常**（`module/exception.py`）。

## E. 结果确认

**除视觉外的确认通道存在，但不是"读游戏日志"**：
- March7th 直接**读写游戏注册表**：分辨率、自动战斗、二倍速、UID、自动 HDR
  （`tasks/game/starrailcontroller.py:21-157`）。
- March7th 云游戏走 CDP `Input.dispatchMouseEvent`/`Input.dispatchKeyEvent`，不经窗口消息
  （`module/automation/cdp_input.py`）。
- BetterGI 另有 Gamepad 与 WebSDK(WebView2) 输入后端（`Core/Input/Backends/Gamepad`、`WebSdk/IWebInputBridge.cs`）。
- **"读游戏日志文件判断结果"——未在任何被调研项目中获取到。**

**失败证据三层**：MaaFW `maa_option.json` 的 `save_on_error`（默认 true，失败存当前截图）、`save_draw`
（存全部识别可视化图）、`logging`（`debug/maafw.log`）；`Screencap` 动作可归档到 `log_dir/screencap/`。
MAA（旧）在异常与 `TaskChainError` 时调 `save_fail_img()`（`src/MaaCore/Assistant.cpp:653,680`）。
ALAS 的 RichFileHandler 写日志并保留 `tracebacks_show_locals=True`（含局部变量）。

**最值得抄的是回调协议**：`Tasker.Task.Succeeded/Failed`、`Node.Recognition.Succeeded/Failed`、
`Node.Action.Succeeded/Failed`、`Node.WaitFreezes.Succeeded{reco_ids, elapsed}`
（maafw.com/docs/2.3-CallbackProtocol）——机器可读、细到节点的成败与耗时，比截图更适合 Agent 消费。

## F. 对 MCP/AI Agent 的启发

已有先例：**MaaMCP**（PyPI `maa-mcp`）把 MaaFramework 包成 MCP，Windows 侧"截图与控制均在后台运行，
不占用鼠标键盘"，工具集正是我们要的三类：`ocr`（推荐优先）、`screencap`（默认 720 短边坐标系，
`include_metadata=True` 回传 `image_to_controller.scale/offset`）、
`click`/`double_click`/`swipe`/`input_text`/`click_key`/`keyboard_shortcut`/`scroll`，加 Pipeline 系列
`save_pipeline`/`run_pipeline`/`start_pipeline`/`get_new_messages`（MaaMCP README）。
**它同时暴露"原子动作"与"声明式 Pipeline"两层**——这是最值得复用的架构结论。

## 对 GameMod MCP 的 5 条可直接落地的建议

1. **`ui_find(target, kind, roi=None, threshold=0.8, index=0, order_by="Horizontal", timeout=20000,`
   `rate_limit=500)`** — 合并"找文本/找图/找色"为一个工具，`kind: text|template|color|regex` 区分
   （禁止三个工具各留一个）；返回 `{ok, box:[x,y,w,h], text, score, click_point}`。`roi` 用基准 720p
   相对坐标，内部乘全局 `control_scale`。
2. **`ui_click(target=None, kind=..., box=None, jitter="gaussian"|"none", button="left", expect=None)`**
   — 把"识别 + 点击"合成一次调用（对应 `ClickSelf`），`target` 缺省时点上一个 `box`；识别失败即
   `ok:false`，绝不点 (0,0)。
3. **`ui_wait(expect, roi=None, kind=..., timeout=20000, rate_limit=500, freeze_ms=0,`
   `freeze_threshold=0.95)`** — 落地 MaaFW 的 `while(!hit && !timeout)` + `wait_freezes`，返回
   `{ok, elapsed, polls, last_box, last_text}`；失败时**必须回传最后一次截图路径**（等价 `save_on_error`）。
4. **`screencap(roi=None, save=True, include_metadata=True)` + `ocr(roi, expected=None,`
   `only_rec=False, threshold=0.3, replace=[])`** — 与 MaaMCP 对齐：`ocr` 必须只对 ROI 跑，并回传
   `image_to_controller{scale,offset}`，否则 Agent 拿到裁剪图坐标而点错位置（MaaMCP 专门写进 README 的坑）。
5. **`click(windows_backend="auto", allow_background=True)` + `probe_log(path, pattern, since)`**
   — 输入后端照 MaaFW 枚举实现"auto 探测"（PostMessage 优先，失败降级 Seize 并如实 `background:false`）；
   另加**游戏日志/标准输出 tail 工具**补齐 Bot 项目普遍缺失的一环——用户明确要求"通过日志确认结果"，
   而这恰是所有被调研项目**未获取到**的能力，是本项目差异化的关键。
