### 7. 对我们项目最有参考价值的 7 条纪律（原文）

1. **给「深度」下定义并让它可被机器检查，而非靠目录名。** 建议加
   `devtools/verify_test_layering.py`：静态解析每个 `verify_*.py` 的 import，
   单元级脚本 import 会话对象/注入器/浏览器驱动即报红。
2. **真值分层 + 「模拟的东西不能证明真系统行为」写成硬规矩。** mock 掉
   Frida/真机/真引擎的脚本输出必须显式带 `evidence_kind: "simulated"`，
   **禁止**用它支撑「引擎/真机可用」。
3. **「跳过」必须具名、机器可读、且默认不是通过。** 升级 `devtools/samples.py`：
   跳过打印固定 skip 标记 + 缺失的环境变量名，提供 `--strict` 把 skip 变失败；
   汇总脚本分列 pass/fail/skip，**禁止**把 skip 计入通过率。
4. **门禁的「非空转保证」—— 扫到空集合的检查等于没有检查。** 对所有 verify 脚本
   加两条自检：**(a)** 实际断言条目数 > 0；**(b)** 被扫描目标集合与预期来源一致。
   REA 的教训原文：裸 `if (!available) return;` 让整条 lane
   「report green without executing anything」。
5. **生成物与手写物物理分离，各有「漂移即报红」检查。**
6. **同一改动要同步的落点列成表 + 脚本双向校验，且必须扫 Markdown 代码块。**
   REA 点名教训：SKILL.md 配方里留着已删除工具「**没被任何检查发现，因为它在
   ```python 代码块里、不带反引号**」。
7. **Agent 的正确性不能由文字启发式判定。** 判据应是**能对上被测系统产出的
   客观值 + 引用的证据记录本身能复现该值**。
