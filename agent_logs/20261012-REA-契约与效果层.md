### 1. 工具契约的单一真源

**一个工具的全部面向调用方的信息在一个对象里**（`toolContractTypes.ts:43-61`）：

```ts
export interface ToolContract<Name, InputSchema, OutputSchema> {
  readonly name: Name;
  readonly title: string;
  readonly description: string;
  readonly kind: ToolKind;
  readonly inputSchema: InputSchema;
  readonly outputSchema: OutputSchema;
  readonly effects: ToolEffects;
  readonly annotations: ToolAnnotations;
  readonly examples: readonly ToolExample[];
}
```

**聚合真源**：`toolContracts.ts:28-54` 的 `TOOL_CONTRACTS` 把 25 个分册数组展开成一个
有序清单，注释：「Complete ordered public inventory used by registration and
verification.」并提供 `toolContract(name)`（:57-72）**按名字取回精确类型**，
找不到即 `throw new Error("Missing tool contract: " + name)`（:70）。

**工厂函数模式**（避免每个工具手写 9 个字段）——每个分册一个：
- `officialToolContracts.ts:21-36` 的 `official()`：强制 `inputSchema.strict()`，
  `kind: "official-proxy"`，`outputSchema` 从组里取，`examples` 自动生成。
- `sessionToolContracts.ts:37-53` 的 `session()`：`kind: "session"`。
- 两者都 `satisfies ToolContract<...>` —— **类型层面强制字段齐全**，
  漏了任何一个字段是编译错误，不是运行时错误。

### 2. 效果声明与注解派生（最关键的一节）

`toolEffects.ts:2-22` 声明 **10 个效果位**：
`mutatesTarget` / `mutatesSession` / `writesFilesystem` / `launchesProcess` /
`accessesNetwork` / `changesUiState` / `mayDiscardData` / `executesForeignCode` /
`mutatesDevice` / `idempotent`。

默认全 false、`idempotent` 默认 true（:32-44），并有四个预设
（`evidence` / `nativeEvidence` / `browserEvidence` / `sessionEvidence`，:46-52）。

**`TOOL_EFFECTS`（:55-541）是一个显式审计表**：每个公开工具名一条，
一个都不许漏。

**注解是派生的，不是手写的**（:544-565）：

```ts
export const annotationsFromEffects = (value: ToolEffects): DerivedToolAnnotations => ({
  readOnlyHint: !(value.mutatesTarget || value.mutatesSession ||
    value.writesFilesystem || value.launchesProcess || value.accessesNetwork ||
    value.changesUiState || value.mayDiscardData || value.executesForeignCode ||
    value.mutatesDevice),
  // MCP defines destructive as possibly non-additive changes to the environment.
  // Running foreign code or changing a device cannot be bounded to additive
  // effects, so either one is destructive even without data loss.
  destructiveHint: value.mayDiscardData || value.executesForeignCode || value.mutatesDevice,
  idempotentHint: value.idempotent,
  openWorldHint: value.launchesProcess || value.accessesNetwork,
});
```

**「忘了表态就报错」**（:568-573）：

```ts
export const toolContractMetadata = (name: string) => {
  const audited = TOOL_EFFECTS[name];
  if (audited === undefined) throw new Error(`Missing effect audit for ${name}`);
  ...
};
```

即：新增工具若不写效果声明，**注册期直接抛错**（不是静默用 MCP 的保守默认）。
这比我们的 `verify_tool_annotations.py`（静态表，跑测试才发现）**更早失败**。

### 3. 输出模式的组织

- `toolOutputSchemaPrimitives.ts`：底层可复用 schema 片段（如
  `toolAvailabilityFacts`、`clientFeatureAvailabilitySchema`），
  并导出 `TOOL_EFFECT_NAMES` / `TOOL_ANNOTATION_NAMES`（:399-404）
  —— **从 schema 的键动态取**，不是手抄。
- `toolOutputSchemaGroups.ts`：按工具族分组的输出 schema 字典
  （`officialOutputSchemas` / `sessionOutputSchemas` / …）。
- `requireOutputSchema(group, name)`：从组里按名取输出 schema，
  找不到即报错 —— 与 `toolContractMetadata` 同一形状的「缺失即失败」。

### 4. schema 呈现层（为什么存在）

`compactInputSchema.ts:7-9` 的注释说明了真实约束：某些客户端（Kimi→Moonshot）
会把 schema-local `$ref` **展开**后再发，所以「广告用」schema 必须在**展开后**
仍然放得下（实测 13.7 KB 被拒）。因此：

- 有一层把 `$ref` 换成**内联但精简**的形式（`presentation: "inline" | "reduced"`）；
- **服务端校验仍用完整 schema**（注释原文：Canonical server-side validation
  remains unchanged）；
- 保留 `description` / `examples` / `default` / `title`（:12），
  即**不牺牲给模型的提示**，只压缩结构。

→ **这一层我们不需要**：我们的工具参数用 Python 类型注解声明，
本来就不发 `$ref`，没有「展开后超限」的问题。（已写入主文档 §4 不采纳项）

### 5. 错误契约

`errorSchemas.ts:5-16` 的 `category`（10 值）：
`invalid_input` / `unsupported_provider` / `unsupported_target` /
`integrity_mismatch` / `truncated` / `cancelled` / `timeout` /
`resource_constraint` / `unavailable` / `execution_failure`。

公共字段（:22-27）：`category` / `message`(非空) / `retryable`(bool) /
`remediation`(`{action}`，**必填**) / `details`(可选)。

**21 个 code** 组成 discriminated union（:35-69），
其中 `artifact_integrity_mismatch` 带**专属** details 结构（:46-59）。

**「错误定义在契约层」意味着**：错误是**产品面的一部分**，与工具 schema 一样
被生成成 JSON Schema（:99-101 `analysisErrorJsonSchema`）、
被文档化（`docs/error-contract.schema.json`）、被 CLI 与 MCP **共用**
（`analysisCliErrorEnvelopeSchema`:72-96 的 superRefine 要求 CLI 错误信封里
必须含一个**规范的** analysis error projection）。

**对照我们**：我们 `_err(msg, **kw)` 有 131 个调用点，返回
`{ok:false, error:<自由文本>}` —— **没有 `retryable`、没有 `remediation`、
没有机器可读的分类**（实测：`server.py` 里 `retryable|remediation` 零命中）。
这与 REA 的差距不是「字段少几个」，而是**客户端无法据错误决定该不该重试**。

### 6. 注册层

`contractToolHandler.ts:28-81` 是唯一把契约绑到 handler 的地方：

```ts
export const createContractToolHandler = (server, service, logger, ...) =>
  (contract: ToolContract<TOperation>) =>
    createEvidenceToolHandler(server, (input, options) =>
      service.execute(contract.name, input, options), ...)(contract);
```

要点：
- handler 拿到的 `contract` 就是那个真源对象，`contract.name` 直接作为 operation 名
  —— **不存在「契约说 A、注册成 B」的可能**；
- `server.delivery.toEvidenceToolResult(result.value, contract, recorded)`
  （:67-71）用契约做输出投影；
- `toolRegistrationOptions(contract)` 统一生成注册选项。

### 8. 核心不变式清单

| # | 不变式 | 由什么强制 |
|---|---|---|
| 1 | 每个工具的全部元数据在**一个**对象里 | `ToolContract` 接口 + `satisfies` |
| 2 | 新增工具必须显式声明效果 | `toolContractMetadata` 缺即 `throw` |
| 3 | MCP 注解**只能**从效果派生 | `annotationsFromEffects` 是唯一产出点 |
| 4 | 输出 schema 必须存在 | `requireOutputSchema` 缺即报错 |
| 5 | 契约里的工具必须真的被注册 | 目录生成器比对 SDK 广告，缺即抛错 |
| 6 | 错误是产品面的一部分 | 契约层定义 + 生成 JSON Schema + CLI/MCP 共用 |
| 7 | 表示层唯一所有者 | `architecture-guards.mjs` 源码级扫 |
| 8 | 测试文件必须恰好被发现一次 | `verify-test-discovery.mjs` |
| 9 | 分层依赖只许向内 | `verify-module-boundaries.mjs` |

**其中最值得我们对齐的是 #2 与 #3**：我们目前是「手写 `_ann(...)`
+ 静态表验证」，REA 是「声明效果位 → 机器派生注解 → 缺声明就崩」。
后者的好处是**注解不可能自相矛盾**，因为它不是人手写的。
我们已在 `_ann()` 里做了「只读 + destroy=True 直接抛错」的**局部**防矛盾
（`server.py:378-382`）——REA 的做法是把这个思路推广到全部 4 个位。
