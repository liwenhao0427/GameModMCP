# 三个「Agent 操作桌面/游戏窗口」MCP 项目调研

调研方式：web_search 不可用，全部经 web_fetch 直抓 GitHub API / jsDelivr CDN（raw.githubusercontent 在本机 fetch failed）。三仓库均确认存在：podium-mcp（main, MIT, 51 tools）、windows-computer-use-mcp（main, MIT, 24 tools）、fivem-mcp（**master**, MIT, v0.5）。

---

## 1. hoainho/podium-mcp

**输入模拟**：不是 SendInput。手势走原生后端优先级 `idb → mobilecli → Maestro`（README「Native-first gesture backend」），探针结果缓存在 `lib/native.ts`（含负缓存 TTL）。Maestro 回退时生成最小 flow 并用 `launchApp: { stopApp: false }` 把 app 带到前台且**不重启**以保住状态。每个结果回报实际使用的 `backend`。目标平台是 iOS/Android，**未涉及反作弊**；也**未提及 focus stealing**（移动端无此问题）。

**截图/视觉**：`screenshot` 工具**返回 `path` + `byteSize`，不返回 base64**（README 原文：「Returns `path` + `byteSize` (no base64 bloat)」）。最关键的一句在 `src/lib/oracle.ts` 文件头：「**Screenshots are NEVER an oracle.**」视觉不参与断言。

**证据式断言**：三级 oracle ladder——`WebView-DOM > native a11y > Maestro`。核心类型 `VisibleResult { visible: boolean|null; via: "webview-dom"|"native-a11y"|"maestro"|"unverifiable" }`。`visible` 为 **null = 无法验证**，与 false（确认不存在）严格区分。防自欺的三条硬机制：
- `assert_not_visible` **fail closed**：若 WebView 的 DOM 读不到，返回 `UNVERIFIABLE — refusing to assert absence (fail-closed). The WebView DOM could not be read; an empty native tree is NOT proof of absence.`
- 每个 verdict 都**点名产生它的 oracle**（`via`），让 Agent 能自行加权置信度。
- 源码注释直接写明动机：空的原生 a11y 树「would make "not visible" assertions falsely pass」。

**no-vision canvas brain**：既不是引擎内部钩子，也不是 accessibility tree。它通过 CDP `eval` 向页面**注入 JS 桥**（`buildCanvasBridgeScript()` 装 `window.__podiumCanvas`），在 `document` 内自动探测并**遍历 6 个框架的内存场景图**（Pixi/Konva/Fabric/Phaser/Three/Babylon），把节点几何换算成 tap-ready 的 CSS px，再叠加 WebView 屏幕原点得到绝对坐标。`canvas-a11y.ts`（Flutter/ARIA）与 `canvas-vision.ts` 都明确标注为「scaffolding, not wired (#9)」。Unity 那条是**另一个**实验路径（Alttester / `window.__podiumEngine`），README 自承「not yet validated against a live Unity build」。**没有框架或 WebView 不可 inspect 时 fail closed，绝不退化成视觉**。

**等待/超时**：`wait_for_element` 轮询 oracle（默认 10000ms），`assert_visible` 默认 3000ms、`assert_not_visible` 默认 1500ms；超时返回明确错误 `not visible within {budget}ms (oracle: X)`。断言失败是 MCP tool error，不是静默 pass。

**防目标错选**：`resolveIntent` 要求 `score ≥ 0.6` **且**领先亚军 `≥ 0.15` 才 `confidentEnough`；否则 `canvas_tap` **不点**，返回 candidates（含 score + `reasons[]` 人类可读证据，如 `["text=close","top-right corner"]`）。

## 2. betrayzl/windows-computer-use-mcp

**输入模拟**：`native/src/input.rs` 用 **enigo** crate（Windows 后端即 **SendInput**；键鼠均非 PostMessage、非驱动级）。组合键实现为「按下修饰键→sleep 10ms→主键→sleep 50ms→释放」，并额外 `release_all_modifiers()`（连发两轮 + 10ms 间隔）防按键卡死。**未提到反作弊**；README 反而以「降低封号风险」为卖点（自称模拟人手比 API 自动化更难被识别），但**没有任何技术证据**。**focus stealing 是明确讨论的难点**：`focus_app` 用「6-level strategy including UI Automation bypass for elevated windows」；`click({processName})` 会先自动聚焦，`ensureForeground()` 重试 5 次 / 3s 上限并在 250ms 后**二次确认稳定性**，失败直接 throw，不裸点。

**截图/视觉**：**DXGI Desktop Duplication**（`capture.rs`：`IDXGIOutputDuplication::DuplicateOutput`，先跳 3 帧 warm-up，`AcquireNextFrame` 100ms×10 重试，MSAA `ResolveSubresource`，staging texture + `Map`）。返回给 Agent 的是 **base64 JPEG**（MCP image content block，`mimeType: image/jpeg`），**不是文件路径**。省 token 手段齐全：`imageops::resize` CatmullRom 按 `max_width/max_height` 等比降采样、JPEG quality 0.75、`capture_region` 先按帧边界 clip 再裁再编。README 标注各工具 token 量级：screenshot ~50k / capture_region ~5k / perceive ~1k / get_ui_elements ~500。**遮挡检测**：`perceive()` 比对前台进程与 `targetProcess`，不在前台就返回中文 `warning` 字段并给出 `focus_app` 补救建议；工具描述亦为「避免操作被遮挡窗口」。README 另承认 VM/RDP 无 GPU 时截图全黑，建议改用无需 GPU 的 UIA 路径。

**证据式断言**：**未获取到**——本项目没有 assert/verify 类工具，24 个工具全是感知与动作。

**等待/超时**：只有 `wait({duration})` **盲等**，README 仅说「Useful for waiting on UI animations」。**没有等待画面稳定、也没有等待元素出现**的机制。

## 3. ziyacivan/fivem-mcp

**输入模拟**：**SendInput**，经 koffi FFI 调 `user32.dll`，在 `src/win/keys.ts` 手工构造 40 字节 INPUT 结构。两个硬细节：
- 键盘用 `KEYEVENTF_SCANCODE` + Set-1 扫描码，源码注释：「GTA reads the keyboard through DirectInput and raw input, which key off the scan code, not the virtual key」；README 直说「Real scan-code input — **GTA's DirectInput ignores VK-only injection**」。
- 字面文本走 `KEYEVENTF_UNICODE`（F8 控制台 / chat NUI 读这个通道）；鼠标绝对定位用 `MOUSEEVENTF_ABSOLUTE` + 0–65535 归一化，相对 dx/dy 驱动相机。

`sendInputs()` 会**校验投递条数**，不等即 throw：「SendInput delivered n/N events — is the game running elevated while this tool is not? Windows UIPI blocks synthetic input from lower-integrity processes.」

**反作弊**：**未获取到**（无任何相关声明）。**focus stealing 是重点**：所有输入/截图工具都过 `ensureGameFocused()`；`focusWindow()` 走 `SW_RESTORE → SetForegroundWindow → AttachThreadInput(fgThread, selfThread)` 绕过 Windows 前台锁定 → `SwitchToThisWindow`，失败给出 `could not bring the game window to the foreground (Alt-Tab lock?)`。**并用 `savedForeground` + `restore_focus` 把偷走的焦点还回去**。另有一条**完全不抢焦点**的输入通道：`client_command` 经 devcon 向运行中客户端的 F8 控制台打字（README：「nothing steals focus」）。

**截图/视觉**：不是 DXGI，而是 **PrintWindow(PW_RENDERFULLCONTENT)**，swapchain 返回黑帧时回退到屏幕 **BitBlt**（此时窗口必须不被遮挡，故先聚焦）。用 `measureBrightness()` 采样统计**非黑像素比例**来自动判定黑帧。返回 base64 PNG（image content block）。省 token：`maxSide` 默认 900 可降到 640、`crop` 矩形，工具描述带成本警告「every screenshot stays in the transcript and is re-sent on every later turn」。

**证据式断言**：`wait_for_console` —— README 明写「Block until a line matching a regex appears — **your assertion primitive**」。`test_resource` prompt 要求输出**证据表**：每行 PASS/FAIL 必须**引用决定它的确切控制台行（channel + message）或坐标**，并明令「Anything unverifiable is listed as UNVERIFIED, not passed」「never assume a step passed」。超时由 `FIVEM_COMMAND_TIMEOUT_MS`(5000) / `FIVEM_QUIET_MS`(400) 控制。无「画面稳定」检测。

## 对本项目可借鉴的 5 条

1. **把「无法验证」做成第三态，而不是 false**。podium 的 `visible: true|false|null` + `via` 字段（并 `via: "unverifiable"` 单列）直接对应我们的 `ok:false + error`；可借到 `find_hook_target`/token 对账上：**「静态 token 与运行时 token 不一致」应当是一个独立的、可区分的失败态**，而不是笼统的 false 或空列表。
2. **断言必须携带可证伪的证据串**。podium 的 `reasons: ["text=close","top-right corner"]` 与 fivem 的「PASS/FAIL 每行引用确切控制台行」是同一设计：让 Agent 无法把「看起来对」当「已证实」。我们的事件返回可加 `evidence` 字段（如 `matched_by: "token"`, `static_token`, `runtime_token`）。
3. **fail-closed 优于猜测**。podium 在 DOM 不可读时**拒绝**断言「不存在」；`canvas_tap` 在 score<0.6 或领先<0.15 时**不点击**。这与本项目「拒绝重载猜测、返回 candidates」的既有做法同源，可复用到 AOB 扫描：多命中且无消歧依据时应拒绝，而不是取第一个。
4. **优先级阶梯 + 显式告知用了哪一级**。podium 的 `WebView-DOM > a11y > Maestro` 与本项目 `静态元数据 → 运行时探针` 是同构的；把「这次结论来自哪一级」写进返回值（如 `source: "metadata" | "runtime"`），可防止 Agent 把静态推断当运行时实测。
5. **成本与副作用要写进工具描述本身**。fivem 在 `screenshot` 描述里写明「每张截图会留在 transcript 并在后续每轮重发」，betryzl 在 README 给每个感知工具标 token 量级（~50k/~5k/~1k/~500）。我们的 `search_classes('', limit=2000)` 实测 856 KB，同理应在工具描述里直接标注「大结果请配合 pattern/limit」，而不是只在 AGENTS.md 里约定。
