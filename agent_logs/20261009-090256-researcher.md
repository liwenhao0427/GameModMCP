## 问题 1：如何找到类的「活对象实例」

**结论：可行（有条件的）。** `il2cpp_class_get_instances` **不存在**；
真正的实例遍历靠 **GC liveness / memory snapshot** 两条官方导出路径。

**证据 1 — 没有 `*_get_instances`。** `frida-il2cpp-bridge` 的 `lib/exports.ts`
是它绑定的**全部** il2cpp 导出清单，逐条核对：有 `gcForEachHeap`(`il2cpp_gc_foreach_heap`)、
`gcHandleGetTarget`(`il2cpp_gchandle_get_target`)、`memorySnapshotCapture`
(`il2cpp_capture_memory_snapshot`)、`memorySnapshotGetClasses/GetObjects`、
`livenessCalculationBegin/FromStatics/End`(`il2cpp_unity_liveness_calculation_*`)、
`livenessAllocateStruct/Finalize/FreeStruct`，
**没有任何名为 `il2cpp_class_get_instances` / `il2cpp_object_get_instances` 的导出**。

**证据 2 — `frida-il2cpp-bridge` 确实实现了「遍历某类所有实例」，就是 `gc.choose(klass)`。**
`lib/gc.ts` 原文注释：`Returns the heap allocated objects of the specified class. This variant reads GC descriptors.`
实现分两支（原文代码）：
```ts
if (!Il2Cpp.exports.livenessCalculationBegin.isNull()) {
    const state = Il2Cpp.exports.livenessCalculationBegin(klass, 0, chooseCallback, NULL, onWorld, onWorld);
    Il2Cpp.exports.livenessCalculationFromStatics(state);
    Il2Cpp.exports.livenessCalculationEnd(state);
} else {
    this.stopWorld();                     // 老 Unity 走这条，需停世界
    const state = Il2Cpp.exports.livenessAllocateStruct(klass, 0, chooseCallback, NULL, reallocCallback);
    Il2Cpp.exports.livenessCalculationFromStatics(state);
    Il2Cpp.exports.livenessFinalize(state);
    this.startWorld();
}
```
回调签名 `(objects: NativePointer, size: number)`，按 `Process.pointerSize` 步进读出对象指针。
**这直接回答了「纯 C# 类的实例」——可行，且不依赖 UnityEngine.Object。**

**证据 3 — `MemorySnapshot` 是「全堆」而非「按类」。** `lib/cmodules/memory-snapshot.c` 内联 CModule：
```c
void ** il2cpp_memory_snapshot_get_objects(const Il2CppManagedMemorySnapshot *snapshot, uint32_t *size) {
    *size = snapshot->gc_handles.tracked_object_count;
    return snapshot->gc_handles.pointers_to_objects;
}
```
返回的是 **GC handles 全量对象**；`get_classes` 走的是 `metadata_snapshot.types`。
所以要用它找某个类，**必须自己对每个对象取 `il2cpp_object_get_class` 过滤**，成本高。

**替代路径 — `Resources.FindObjectsOfTypeAll` 可行，仅限 `UnityEngine.Object` 子类。**
官方文档原文：`This method can return any type of Unity object that is loaded... Unlike Object.FindObjectsOfType, this method also lists disabled objects.`
并明确警告 `Note: This method is very slow. Avoid using it every frame.`
**前置条件（Type 对象怎么拿）**：导出链是
`il2cpp_class_from_name` → `il2cpp_class_get_type`(`classGetType`) → `il2cpp_type_get_object`(`typeGetObject`，得到 `System.Type` 对象)，
再以该 `System.Type` 调用 `FindObjectsOfTypeAll(Type)`。三个导出在 `exports.ts` 中均已确认存在。

**结论排序**：单例/纯 C# 类 → `gc.choose(klass)`（首选，直接、精确）；
需要 GameObject/MonoBehaviour 且要拿 `transform`/`gameObject` → `FindObjectsOfTypeAll`。
Object 的 GC 堆扫描可行但**没有按类索引**，只在上述都不可用时才用。

## 问题 2：语义化模拟 UI 输入

**结论：两条都可行，但推荐 `ExecuteEvents.Execute`，`onClick.Invoke()` 属降级方案。**

**证据 1 — `ExecuteEvents.Execute` 签名（UGUI 官方 API 文档原文）：**
```csharp
public static bool Execute<T>(GameObject target, BaseEventData eventData,
    ExecuteEvents.EventFunction<T> functor) where T : IEventSystemHandler
```
且 functor 是现成的静态属性，文档原文：
`public static ExecuteEvents.EventFunction<IPointerClickHandler> pointerClickHandler { get; }`
→ 因此调用形式是 **`Execute<IPointerClickHandler>(go, pointerEventData, ExecuteEvents.pointerClickHandler)`**。
**前置条件**：① 目标 `GameObject`；② 一个 `PointerEventData` 实例（继承自 `BaseEventData`），
需以 `EventSystem.current` 为构造参数并设置 `button`/`position`；③ 场景里有 `EventSystem`。
**Frida 侧的坑**：`Execute<T>` 是**泛型方法**，IL2CPP 下需先 `inflate` 出具体实例
（`frida-il2cpp-bridge` 的 `Class.inflate(...)` / `Method` 泛型支持）；构造 `PointerEventData` 需要能 new 对象。

**证据 2 — `Button.onClick` 可直接调用，但语义等价性差。** UGUI 官方文档：
`public Button.ButtonClickedEvent onClick { get; set; }`
描述原文：`UnityEvent that is triggered when the button is pressed. Note: Triggered on MouseUp after MouseDown on the same object.`
`Button` 实现 `IPointerClickHandler`，其 `OnPointerClick(PointerEventData)` 内部才 `onClick.Invoke()`。
→ **直接 `Invoke()` 会绕过整个事件管线**：不经过 `Selectable` 的 pressed/selected 状态机、
不校验 `interactable`、不触发 `IPointerDownHandler`/`ISubmitHandler` 等同级监听者。
好处是**最简单、最稳**（不需要 PointerEventData、不需要 EventSystem、不涉及泛型）。
代价是**验收失真**：按钮动画、禁用态、多点触控逻辑都不会被覆盖。

**证据 3 — 与 Windows `SendInput` 模拟屏幕坐标相比：**

| 维度 | 语义化派发（Execute / onClick） | SendInput 屏幕坐标 |
|---|---|---|
| 精度 | 精确到对象，无坐标误差 | 依赖分辨率/缩放/窗口位置，易偏 |
| 后台窗口 | **可后台**，不抢焦点 | 通常需要窗口前台且有焦点 |
| 独占全屏 | 不受影响 | 焦点抢占、误点风险 |
| 覆盖度 | 只覆盖被调用的那一个 handler | 覆盖真实输入栈（含 Input System） |
| 反作弊 | 不改输入 API，但需 Frida 注入（本身即特征） | 会被注入检测/输入时序分析命中 |
| 验收价值 | 需另配断言，否则「点了但游戏没反应」也会算通过 | 更接近真人，但失败模式难归因 |

**结论**：主路径用 `ExecuteEvents.Execute`（真实事件管线）；
对**确认无状态机副作用**的按钮，`onClick.Invoke()` 作为兜底；
`SendInput` 仅用于必须走 Input System 的场景（如 `Input.GetMouseButtonDown` 逻辑）。
注意：**两者都不能证明「游戏真的响应了」**，必须配问题 4 的稳定性/状态断言。

## 问题 3：Frida 截取 Windows 游戏画面

**结论：Frida 内置截图 API —— 未获取到证据（且证据倾向于「不存在」）。**
我完整抓取了 Frida 官方 JS API 文档（`frida/frida-website` 仓库 `_i18n/en/_docs/javascript-api.md`）
并对其做了全文检索：**`Screen` 作为 API 章节不存在**，目录里「Other」段只有
Console/Hexdump/Checksum/Shorthand/Communication/Timing events/Garbage collection/Worker/Cloak/
Profiler/Sampler 系列。全文 `screenshot` 仅 2 处命中，且都是**举例的文件名**
（`Script.load(name, source)` 与 `Script.registerSourceMap` 的示例路径 `/plugins/screenshot.js`），
**不是 API**。→ Frida 侧没有可用截图能力，需外部方案。

**替代方案（真实存在、已核实名字/许可）：**

- **DXcam**（`ra1nty/DXcam`，MIT，804★，Python）：基于 **Desktop Duplication API**。
  README 原文：`Stable capture for full-screen exclusive Direct3D apps`、
  `Support DXGI / Windows Graphics Capture dual backend`，
  可 `backend="dxgi"`（默认，Desktop Duplication）或 `backend="winrt"`（Windows Graphics Capture）。
  自测基准：**239.19 FPS @1080p**，同场景 python-mss 75.87、D3DShot 118.36。
  零拷贝 `grab_view()`、区域截取 `region=(l,t,r,b)`、`get_latest_frame(with_timestamp=True)`。
- **python-mss**（`BoboTiG/python-mss`，MIT，1286★，Python，纯 ctypes 无依赖）：
  跨平台、`MSS()` + `sct.shot()`。**不含 GPU 加速**，速度显著低于 DXcam（75.87 vs 239.19 FPS）。
- **windows-capture**（`NiiightmareXD/windows-capture`，MIT，514★，Rust + Python 绑定）：
  使用 **Windows Graphics Capture API**，2.0.1 起**新增 DXGI Desktop Duplication API 支持**；
  官方示例 `DxgiDuplicationApi::new(monitor)` + `acquire_next_frame(33)` + `save_as_image(...)`。

**对独占全屏 / DX11 / DX12**：DXGI Desktop Duplication 与 WGC 都工作在 DWM 合成层。
DXcam 明确声称对**全屏独占 D3D 游戏**稳定（README 原文）。但更稳妥的工程结论是：
**优先让游戏跑「无边框窗口（Borderless Windowed）」**，此时两种后端都最可靠；
真正的独占全屏在部分机器/驱动上会失败或抓不到帧。**未获取到**权威的「DX12 独占全屏必然失败」的官方文档证据。

## 问题 4：判断「画面稳定 / 加载完成」（不靠截图）

**结论：可行，且有多条元数据路径，优先于截图比对。**

**证据 1 — `Application.isLoadingLevel` 已废弃，不要用。** Unity 官方文档原文：
`Method group is Obsolete`、`Obsolete - please use the newer SceneManager class to handle all Scene loading operations.`
`isLoadingLevel returns true if a level load was requested this frame already.`

**证据 2 — `SceneManager.sceneLoaded` 是官方推荐的事件入口。** 文档原文给出**精确的执行顺序**：
`Unity raises the SceneManager.sceneLoaded event and invokes the associated callback after OnEnable but before Start.`
回调签名 `MyMethod(Scene, LoadSceneMode)`。
→ 在 Frida 里即：**Hook / 订阅 `SceneManager.sceneLoaded`**（`frida-il2cpp-bridge` 支持拦截方法）。
注意其语义是「加载完成且 OnEnable 跑完」，但**早于该场景所有 `Start`**，
所以它标记的是「场景就绪」而非「首帧渲染完毕」——**不能单独当作「可以开始验收」**。

**证据 3 — `Scene.isLoaded` 可轮询。** 文档原文：
`IsLoaded is set to true after loading has completed and objects have been enabled.`

**推荐组合（不靠截图）**：
① Hook `SceneManager.sceneLoaded` → 知道切换发生；
② 轮询 `Scene.isLoaded` → 确认加载完成；
③ **帧计数器（`Time.frameCount`）连续 N 帧不变或稳定** → 确认渲染循环不再剧烈跳变；
④ 断言「预期对象已出现」（`gc.choose`／`FindObjectsOfTypeAll` 能拿到目标类的实例）。

**证据 4 — 业界做法（Playwright 的「等待」范式，可直接类比）。** Playwright 文档原文：
`Playwright performs a range of actionability checks on the elements before making actions... It auto-waits for all the relevant checks to pass`
其 click 的检查项为：`Visible / Stable / Receives Events / Enabled`，其中
**`Element is considered stable when it has maintained the same bounding box for at least two consecutive animation frames.`**
→ 这正是「画面稳定」的通用定义：**连续两帧（对游戏可放宽到 N 帧）几何/状态不变**。
本项目可把 Playwright 的四个语义位映射为：`Visible`→对象存在且 `activeInHierarchy`、
`Stable`→状态字段连续 N 帧不变、`Receives Events`→目标 handler 存在、
`Enabled`→`Selectable.interactable` 等。

## 对本项目的 3-5 条关键结论

1. **实例定位不必靠猜，也不必扫堆**：`il2cpp_unity_liveness_calculation_*`（即 `gc.choose(klass)`）
   是**官方导出**且 `frida-il2cpp-bridge` 已实现，能直接拿到**任意类（含纯 C# 类）**的全部存活实例；
   这是本项目「元数据优先」最有力的一块拼图。`MemorySnapshot` 只能给全堆对象，需自行按类过滤。
2. **UI 输入首选 `ExecuteEvents.Execute<IPointerClickHandler>(go, eventData, ExecuteEvents.pointerClickHandler)`**，
   它走真实事件管线；`Button.onClick.Invoke()` 会绕过状态机与 `interactable` 校验，
   只能当兜底，且**它「成功返回」不代表游戏真的响应了**。
3. **Frida 不提供截图**（已全文核实官方 JS API 文档，`Screen`/截图 API 不存在），
   截图必须外挂；Python 侧 **DXcam（MIT，Desktop Duplication + WGC 双后端，239 FPS）** 是当前最佳选择，
   并建议**强制游戏走无边框窗口**以规避独占全屏的不确定性。
4. **「加载完成」应做成状态机而非一次判断**：Hook `SceneManager.sceneLoaded` + 轮询 `Scene.isLoaded`
   + 帧计数器稳定 + 目标对象存在，四者同时满足才判定可验收；
   `Application.isLoadingLevel` 已废弃，禁止使用。
5. **验收不能只看「动作派发成功」**：所有语义化点击都要配一条独立的**状态断言**
   （复用结论 1 的实例读取去比对字段值），否则会得到「全绿但游戏无变化」的假成功
   ——这正是本项目 AGENTS.md 反复强调的「假成功比失败更糟」。
