新增(运行时): find_instances —— 枚举类的活对象实例（拿 instance 指针的正路）

在此之前，拿一个对象指针的**唯一**办法是「Hook 一个恰好会收到该对象的
函数，从 args[0] 捡」—— 碰运气，与本项目「元数据优先」相悖。
本工具直接问运行时「这个类现在有哪些实例」。

实现走 GC liveness（Unity 自家内存分析器用的 il2cpp_unity_liveness_*）：
stopWorld → allocate_struct → calculation_from_statics → finalize →
startWorld → free_struct。这是 frida-il2cpp-bridge 的 gc.choose 走的
allocate_struct 分支（calculation_begin 分支在本机样本上不存在）。

真机验证（PathOfIdle, IL2CPP）12/12 通过：
  find_instances(Transform, max_count=5) → count=5, overflow=true,
  instances[].class_name="RectTransform", exact=0, derived=5
关键证据链：独立 read_memory 读对象头拿 klass，再解出类名，
与工具报的 class_name 完全一致 —— 证明拿到的是该类的活实例而非野指针。

实测踩到并修掉的四个问题（都写进了注释与文档）：

1. il2cpp_class_is_valuetype 的返回值不能直接当布尔。本探针统一按
   'pointer' 包装导出，C 的 false 变成「非空但内容为 0」的指针对象，
   JS 里任何对象都 truthy → 每个类都被判成值类型（Transform 被误拒）。
   修法：.toInt32() !== 0。
2. liveness 返回的是「该类**及其派生类**」的实例 —— 实测 Transform
   拿回的全是 RectTransform。语义如此，但拿基类偏移读派生类实例
   可能出错。故返回 instances[].class_name + exact/derived_count +
   class_name_counts，并在 derived_count>0 时给 note：把静默的错值
   风险变成可见的。
3. fail(msg, extra) 的 extra 藏在 detail 里，而 unsupported 是调用方
   直接读的语义位 —— 验收脚本读顶层读到 None，把引擎限制误判成
   「工具没按契约标注」。修法：工具层把 detail 摊平到顶层。
4. mono_gc_walk_heap 的返回类型必须登记为 pointer（项目不变量，
   非 pointer 的数值返回类型造成过一次真实崩溃）。顺从该规矩 +
   调用处 .toInt32()。

Mono 侧如实声明限制、不用零冒充：Mono 没有 liveness 导出，
mono_gc_walk_heap 的官方头文件（mono/metadata/mono-gc.h）写明
「只在 pre-stop-world 回调内有效」，从 Frida 线程调用不保证有效
（实测 Archon Soul 返回 rc=1/scanned=0）。工具返回 ok:false +
unsupported:true + rc + scanned，错误信息明确写「不能据此断定该实例
不存在」，且**不返回 count**（count:0 会被读成「这个类没有实例」）。
